The pipeline, stage by stage

Collect get the raw audio
01

Search

internet

Query YouTube with Thai scam keywords (fake police, parcel/OTP, investment…) and a few legitimate-call queries. Keeps only clips of sane length; de-dupes.

keywords → data/meta/videos.csv
tool
yt-dlp with extract_flat — pulls metadata only, no media
method
ytsearchN:<query> per Thai keyword (10 scam + 3 legit queries)
filter
duration 30–1800 s · de-dupe by video_id · trim to targets.youtube=20
resumable
new ids appended to existing videos.csv; a source column tags each row
02

Download

internetffmpeg

Pull the best audio for each video, convert to 16 kHz mono WAV, and grab Thai subtitles if they exist. Raw media stays private (never shared).

videos.csv → data/raw/audio/{id}.wav
audio
yt-dlp bestaudio → ffmpeg -ac 1 -ar 16000 = 16 kHz mono WAV (Whisper's native rate)
subs
writesubtitles + writeautomaticsub, lang th, VTT; records has_manual/auto_subs
polite
sleep_s between hits · retries=3 · failures logged, run continues
resumable
skips a clip if its .wav already exists; raw media stays git-ignored
Transcribe + separate turn audio into speaker turns
↓ the same audio feeds two models in parallel ↓
03

Transcribe

GPU

Thai Whisper (large model on Colab) writes down the words, with start/end timestamps per phrase.

→ interim/asr/{id}.json
model
biodatlab/whisper-th-large-v3-combined — Thai fine-tuned Whisper large-v3 (WER ≈ 6.6)
runtime
HF transformers ASR pipeline · fp16 on CUDA (fp32/CPU fallback)
decode
sequential long-form (chunk_length_s=0) → real segment timestamps, not one blob
anti-loop
no_repeat_ngram_size=3, temperature fallback 0→1.0, compression & logprob gates kill "โอ้ โอ้…" hallucinations
note
transformers 5.x drops timestamps → pinned <5
04

Diarize

GPUHF token

pyannote finds who spoke when — the speaker boundaries that separate the scammer from the victim.

→ interim/diar/{id}.rttm
model
pyannote/speaker-diarization-3.1
steps
segmentation-3.0 → speaker embeddings → agglomerative clustering
speakers
min/max_speakers = 2–4 (config; news clips add an anchor)
auth
needs HF_TOKEN + accepted gated terms · CUDA, auto CPU-fallback
output
RTTM — one line per speaker interval (start, dur, SPEAKER_xx)
05

Segment into turns

Merge the two: assign each transcribed phrase to a speaker by time overlap, then join consecutive same-speaker phrases into one turn.

asr + diar → interim/turns/{id}.json
align
each ASR segment → the speaker whose RTTM intervals have max time-overlap (fallback: nearest midpoint)
merge
consecutive same-speaker segments within merge_gap_s=0.75 → one turn
drop
turns shorter than min_turn_s=0.5 or empty
fallback
no RTTM (no token) → everything becomes one speaker, pipeline still runs
output
[{turn_index, speaker, start, end, text}]
Clean + label make it safe and tagged
06

Clean & mask

Normalize Thai text and mask personal data (PDPA): phone → [PHONE], ID → [ID_CARD], account → [ACCOUNT], links → [URL], names → [NAME]. Org names (bank, post, police) are kept — they signal scams.

→ interim/clean/{id}.json
normalize
pythainlp.util.normalize + whitespace collapse
regex mask
ordered: [URL] → [PHONE] (+66/0…) → [ID_CARD] (13 digits) → [ACCOUNT] (10–12)
NER
PyThaiNLP thainer (CRF / python-crfsuite) → PERSON = [NAME]; org names kept (scam signal)
safety
unmasked text_raw kept only in git-ignored interim/ for reviewers (PDPA)
07

Pre-label

Keyword rules make a first guess: is this a scam, which type, and which speaker is the scammer. A starting point for the human — never the final label.

→ data/review/review.csv
rules
substring match of labels/keywords.yaml on each turn
type
scam_type = most keyword hits (tie → priority order); generic markers only → other_scam
roles
scammer = speaker with most scam-content hits · onset = first turn carrying a scam keyword
optional
--llm: local vLLM (OpenAI-compatible) returns JSON {is_scam, scam_type, …}
Review + deliver human-checked output
08

Human review

you

Open the CSV and correct the labels and text by hand. Drop narration / off-topic turns. This is where accuracy comes from — ASR is rough on phone audio.

review.csv → review_done.csv
fill
speaker_role · is_scam · scam_type · keep · text_corrected · notes
drop
mark narrator or keep=0 → excluded at export
format
UTF-8 with BOM so Thai renders in Excel; edit, save as review_done.csv
09

Export

Combine the reviewed labels into the final dataset files plus a stats report. Your edits win over the machine's guesses.

→ data/final/*.csv
coalesce
human columns override the machine pre_* guesses; narrator/keep=0 rows dropped
files
turns.csv (per turn) · conversations.csv (per call, + source) · simple.csv (train-ready)
report
stats.md: videos · turns · hours · scam/not + by-source balance
encoding
UTF-8 with BOM

What you get

turns.csv

One row per speaker turn — the main file: text, role, timing, labels, source.

conversations.csv

One row per call — every turn joined as [ROLE] text, with call-level labels.

simple.csv

Just text, is_scam, scam_type — ready for WangchanBERTa / TF-IDF.

stats.md

Counts of videos, turns, hours, and the scam-vs-not class balance.

fake_authority phishing_otp investment lottery_prize romance other_scam none (legit)
Privacy & copyright. Raw audio and unmasked text never leave the private working folder. The released dataset contains only video id, URL, timestamps, masked text, and labels — personal data is stripped before export.
